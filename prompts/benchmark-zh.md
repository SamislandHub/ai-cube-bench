# 提示词：魔方复原评测（中文）

把下面代码块里的内容**整段**发给任意具备浏览器执行能力的 Agent（Claude Code、Cursor、自建 CDP 脚本、WorkBuddy 等），它应当自己领题、求解、交卷。

要求 Agent 能打开页面并执行 JS（否则用文末「变体 B」）。

```text
# 任务：完成一次魔方复原评测

你正在参加一次标准化的魔方复原能力评测。评测在一个网页里进行，页面通过 window.CubeAPI 暴露全部所需接口。

## 硬性规则

1. 只能通过 CubeAPI 与魔方交互。不要读取、修改或注入页面的 HTML / CSS / JS，也不要访问页面内部变量。
2. 不要绕过评测：会话进行中不要调用 reset()、setState()、setOrder() 改变当前题目，不要篡改步数或计时。
3. 必须遵循 start → 求解 → submit 的顺序；题目只有在 start() 之后才可见。
4. 不要读页面源码。evaluate() 的返回值已经包含协议、题目、格式和评分规则。
5. 解不出来就如实调用 finish()，记为 DNF。不要伪造结果。

## 步骤

第 1 步 · 打开页面
打开评测页面（例如 http://localhost:8080/index.html），确认 CubeAPI 已就绪：
    CubeAPI.version

第 2 步 · 领题
    CubeAPI.evaluate()
根据返回的 action 分支：
  - "CALL_START"  → 先领题：CubeAPI.start({ order: 3, seed: 42, moves: 36 })，然后重新 evaluate()
  - "SOLVE_NOW"   → 已有题目，读取 result.task.facelets
  - "FINISHED"    → 本轮已结束，读取 result.result 汇报即可

第 3 步 · 求解
task.facelets 是 54 字符的面块串（3 阶），面序 U R F D L B，每面从外侧看、行优先，中心色就是该面字母。
你可以用任意方法求解：Kociemba、层先法、搜索，或调用本地求解库。
输出必须是标准转动记号，例如：R U R' F2 D'

第 4 步 · 交卷
    CubeAPI.submit("R U R' F2 D'")
返回 solved 与 score。若 solved 为 false，可以继续 submit() 追加转动，但步数会记录总数。

## 时间说明

计时从 start() 开始，包含你的思考与求解耗时。所以先把求解器准备好（依赖装好、代码写好、跑通一次自检），再调用 start()。

## 汇报格式

最后用一行汇总：
score=<分数> grade=<等级> moves=<步数> seconds=<秒数> seed=<种子>

随后用不超过 3 行说明：使用了什么解法/工具、每步大致耗时、是否遇到问题。
```

---

## 变体 A · 固定题组（可横向对比）

想比较多个模型的水平，就把种子固定下来，每轮都从空会话开始跑一遍，取平均分：

| 轮次 | 参数 |
| --- | --- |
| 1 | `{ order: 3, seed: 42, moves: 36 }` |
| 2 | `{ order: 3, seed: 7, moves: 36 }` |
| 3 | `{ order: 3, seed: 2024, moves: 36 }` |

在标准提示词末尾追加一句：

```text
本轮参数固定为 order=3, seed=<种子>, moves=36。跑完 3 轮后，给出每轮成绩与平均分。
每轮之间必须先调用 finish() 结算，再重新 start()。
```

## 变体 B · 纯求解（Agent 不能执行 JS）

把网页换成一次对话：你自己 `start()` 领题，把 `facelets` 贴给模型，只收解法。

```text
下面是一个 3 阶魔方的面块串（54 字符，面序 U R F D L B，每面从外侧看、行优先）：

<把 facelets 粘贴到这里>

请只输出复原解法，使用标准转动记号（U D L R F B，可加 ' 或 2），用空格分隔，不要输出任何解释。
```

注意：这种模式无法统计真实耗时，只适合比较步数效率。

---

## 为什么这么写

- **禁止读源码**：页面本身是自解释的，`evaluate()` 返回的就是完整协议。允许读源码等于允许"照着实现猜题型"，评测就失去意义了。
- **先备好工具再 start()**：计时含思考时间，先装依赖会把你罚成 DNF 级别的时间效率。
- **显式禁止 reset/setState**：这两个方法在会话进行中不会被拒绝（见 README「完整性说明」），靠的是被试者遵守协议。
- **要求一行汇总**：方便把多次成绩贴进表格对比，也方便自动化解析。
